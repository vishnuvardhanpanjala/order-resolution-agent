## What these numbers do not prove

- The tickets are synthetic and were written by the same person who wrote the policy. Real customers write things we did not think of.
- 60 tickets is small. One ticket is almost 2 points of accuracy.
- The expected outcomes come from our own policy table. If the table is wrong, a "correct" answer can still be bad for the customer.
- The mock systems never lag, never return half-written data, and fail only where we told them to.
- English and Singlish only.
- A live run on the same prompts can move a few points, because models are not fully repeatable.
- No real usage, so no adoption, cycle-time or reopen-rate numbers. See `07_rollout.md` for how those would be measured.
